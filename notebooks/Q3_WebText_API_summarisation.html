3.1 Extract web content into an R data structure

Site chosen and fair-use compliance

I selected the Eurac Research science blog (the article “Can language become environmental data?”), because the site states that its content is licensed under Creative Commons Attribution 4.0, which permits reuse with attribution. Fair-use / ethical scraping measures applied:

  1. robots.txt is checked programmatically before any request.
  2. A descriptive User-Agent is sent.
  3. Requests are rate-limited (2 seconds apart) and only a handful of public pages are fetched.
  4. Only public article text is collected, no personal data, for educational use, and the source is credited (Eurac Research, CC BY 4.0).
START_URL     <- "https://www.eurac.edu/en/blogs/connecting-the-dots/can-language-become-environmental-data"

scrape_page <- function(url) {
  Sys.sleep(2)                                   # polite delay
  resp <- GET(url, UA, timeout(20))
  stop_for_status(resp)
  page <- read_html(content(resp, "text", encoding = "UTF-8"))

  title <- page |> html_element("h1") |> html_text2()

  # try progressively broader selectors for the article body
  paras <- page |> html_elements("article p") |> html_text2()
  if (length(paras) < 3) paras <- page |> html_elements("main p") |> html_text2()
  if (length(paras) < 3) paras <- page |> html_elements("p") |> html_text2()

  tibble(url = url, title = title, para_id = seq_along(paras), text = paras)
}

3.2 Textual preprocessing

Steps: remove empty/very short paragraphs, remove site boilerplate (navigation, cookie, newsletter, social/footer text), remove duplicates, strip HTML remnants, URLs and e-mails, lower-case, remove digits and punctuation, remove stop words and short tokens, lemmatise.

boilerplate <- regex(
  "cookie|newsletter|subscribe|follow us|share|privacy|imprint|work with us|get directions|creative commons|licensed under|access work|choose language|all rights reserved|data scientist working",
  ignore_case = TRUE)

web_clean <- raw_web |>
  mutate(text = str_squish(text)) |>
  filter(nchar(text) > 40,                          # drop menu items / captions
         !str_detect(text, boilerplate)) |>         # drop boilerplate
  distinct(text, .keep_all = TRUE)                  # drop duplicates

clean_text <- function(x) {
  x |>
    str_replace_all("<[^>]+>", " ") |>
    str_replace_all("http\\S+|www\\.\\S+", " ") |>
    str_replace_all("\\S+@\\S+", " ") |>
    str_to_lower() |>
    str_replace_all("[^a-z\\s]", " ") |>
    str_squish()
}

extra_stop <- c("also","can","may","might","one","two","use","used","using","like","et","al")

tokens <- web_clean |>
  mutate(clean = clean_text(text)) |>
  unnest_tokens(word, clean) |>
  filter(!word %in% stop_words$word, !word %in% extra_stop, nchar(word) > 2) |>
  mutate(word = lemmatize_words(word),
         word = if_else(word == "datum", "data", word)) |>
  filter(!word %in% stop_words$word)

3.3 Text summarisation

Two extractive techniques are applied at sentence level:

  • Method 1 - Word-frequency scoring (Luhn style): a sentence scores the sum of the normalised frequencies of its content words, divided by the square root of its length so long sentences are not favoured unfairly.
  • Method 2 - TextRank: sentences are nodes in a graph, edges are TF-IDF cosine similarities, and PageRank identifies the most central sentences.
sentences <- web_clean |>
  select(url, title, text) |>
  unnest_tokens(sentence, text, token = "sentences", to_lower = FALSE) |>
  filter(nchar(sentence) > 40) |>
  mutate(sent_id = row_number())

sent_tokens <- sentences |>
  mutate(clean = clean_text(sentence)) |>
  select(sent_id, clean) |>
  unnest_tokens(word, clean) |>
  filter(!word %in% stop_words$word, !word %in% extra_stop, nchar(word) > 2) |>
  mutate(word = lemmatize_words(word),
         word = if_else(word == "datum", "data", word))

N_SUM <- 5   # sentences in each summary

Method 1: word-frequency scoring

word_w <- sent_tokens |> count(word, name = "n") |> mutate(w = n / max(n))

score_freq <- sent_tokens |>
  left_join(word_w, by = "word") |>
  group_by(sent_id) |>
  summarise(score = sum(w) / sqrt(n()), .groups = "drop") |>
  mutate(method = "Word frequency")

summary_freq <- score_freq |>
  slice_max(score, n = N_SUM, with_ties = FALSE) |>
  arrange(sent_id) |>
  left_join(sentences, by = "sent_id")

Method 2: TextRank

tfidf <- sent_tokens |>
  count(sent_id, word) |>
  bind_tf_idf(word, sent_id, n)

m <- tfidf |> cast_sparse(sent_id, word, tf_idf) |> as.matrix()
m <- m / pmax(sqrt(rowSums(m^2)), 1e-9)            # unit-length rows -> cosine
sim <- m %*% t(m)
diag(sim) <- 0

g  <- graph_from_adjacency_matrix(sim, mode = "undirected", weighted = TRUE)
pr <- page_rank(g)$vector

score_tr <- tibble(sent_id = as.integer(names(pr)), score = pr, method = "TextRank")

summary_tr <- score_tr |>
  slice_max(score, n = N_SUM, with_ties = FALSE) |>
  arrange(sent_id) |>
  left_join(sentences, by = "sent_id")

Findings

Dominant words and theme. After preprocessing, the corpus contained 334 tokens and 209 unique terms from 9 retained paragraphs (27 sentences). The most frequent words were impact (12 occurrences), drought (11), language (10) and environmental (9), followed by information (6), data (5) and water, text, system and capture (4 each). These words show that the article is about using language technologies to extract information about drought impacts from text, treating how people write about environmental change as a data source that complements traditional measurements.

Comparison of the two summaries. The methods agreed on 3 of the 5 sentences. Both selected the sentence about language being “messy, subjective” and rarely a neat source of information, the sentence about combining language technologies with drought assessment to extract when, where and which sectors were affected, and the sentence about analysing a large collection of Italian newspaper articles to build an openly available dataset. These three capture the article’s problem, method and aim, which suggests the article has a clear core message. They differed on two sentences. Word-frequency scoring picked a sentence about the inefficiency of manually reading thousands of articles and another noting that newspaper articles do not simply state a drought’s cause and location, both dense with frequent words such as drought, impact and article. TextRank instead picked two shorter, more general sentences, one on how language captures how environmental change is experienced by society and one on how the texts contain valuable information about how drought affects society. These resemble many other sentences, so they are central in the similarity graph. In my judgement, the frequency summary explains the problem and method more concretely, while TextRank gives a better sense of the article’s overall message. The similarity network (Visualisation 4) supports this: a tightly connected cluster of large nodes sits in the centre, with a few weakly linked sentences at the edges.

Limitations. The corpus is a single short article, so frequencies and graph structure rest on small counts. Both methods are extractive, so they can only copy existing sentences, some of which are long or lose context. Cleaning required judgement: an author byline initially passed the filters and was ranked as an important sentence by both methods until it was removed, and the lemmatiser changed “data” to “datum” until it was corrected. Scraping also depends on the page’s HTML structure, so a layout change could break extraction.

Towards a WebText API. Steps 3.1 to 3.3 can be wrapped into functions such as scrape_url(), clean_text() and summarise_text(), taking a link and returning the cleaned text, the top terms and an N-sentence summary. This is the proof of concept requested and could be deployed as a service (for example with the plumber package), so a user submits a URL and receives the insights.
